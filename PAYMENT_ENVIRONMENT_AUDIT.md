if (!isMockKey) {

Because `this.serverKey` equals `'SB-Mid-server-test-key'`:

### 2. Live Runtime Proof from Cloud API (`https://api.pictolabs.id`)

Invoking the live cloud payment generation endpoint:
```http
POST https://api.pictolabs.id/api/payments/qris
Content-Type: application/json

{
  "boothId": "554147f9-c7f7-47fe-966d-fcbf3223fec4",
  "amount": 1000
}
```

**Actual Response Received from Cloud API:**
```json
{
  "success": true,
  "orderId": "TRX_554147_1790112969137_1ZZD",
  "sessionId": "session_1790112969134_o3595z",
  "amount": 1000,
  "qrisString": "00020101021226590014ID.LINKAJA.WWW01189360091100222071850215TRX_554147_1790112969137_1ZZD0303UMI51440014ID.CO.QRIS.WWW0215ID10200210000010303UMI5204581253033605400410005802ID5909PICTOLABS6007JAKARTA61051234062070703A016304",
  "expiresAt": "2026-09-22T21:40:39.235Z"
}
```

**Anatomy of the Generated `qrisString`:**
- **Tag 26 (Acquirer Info):** `0014ID.LINKAJA.WWW...TRX_554147...0303UMI` (Internal template string, not issued by LinkAja).
- **Tag 51 (National Merchant ID):** `ID1020021000001` (A static dummy national ID, not registered with Bank Indonesia ASPI).
- **Tag 54 (Transaction Amount):** `1000` (Correctly reflects the dynamic price).
- **Tag 59 (Merchant Name):** `PICTOLABS`.
- **Tag 63 (CRC-16 Checksum):** `6304` with **NO 4-hex checksum characters** (standard EMVCo requires e.g. `6304A1F2`).

**Conclusion:** The QR displayed on the Kiosk is **100% locally/internally generated simulation mock data**, NOT a live QR issued by Midtrans Core API.

## 3. What Happens If a Real Banking App Scans This QR?

When a customer or founder attempts to scan this QR code with a live banking or e-wallet application:

| Application | Behavior When Scanned | Funds Deducted? |
|:---|:---|:---:|
| **BCA Mobile / myBCA** | Pop-up: *"Kode QR tidak valid atau format QRIS tidak dikenali"* | **Rp 0 (Safe)** |
| **Livin' by Mandiri** | Pop-up: *"Format QR tidak didukung"* | **Rp 0 (Safe)** |
| **GoPay** | Alert banner: *"QR code tidak valid atau merchant tidak ditemukan"* | **Rp 0 (Safe)** |
| **OVO / DANA** | Toast: *"QR code tidak valid. Pastikan QRIS resmi berlogo Bank Indonesia"* | **Rp 0 (Safe)** |
| **ShopeePay** | Alert: *"Gagal membaca kode QR"* | **Rp 0 (Safe)** |

### Why Real Banking Apps Reject It:
1. **CRC Checksum Missing:** Real payment apps validate Tag 63 using the standard CRC-16 CCITT polynomial before even contacting the payment switch. Because Tag 63 ends at `6304`, the app's scanner rejects it instantly as a malformed payload.
2. **Merchant Not Registered in National Switch:** Even if the payload format were valid, the dummy NMID (`ID1020021000001`) is not registered in Bank Indonesia's central routing switch (Artajasa / Rintis / Alto / Jalin).
3. **Safety Guarantee:** It is impossible for real funds to be deducted by scanning this simulation QR.

## 4. Current Workaround to Test Payment Settlement

Because real e-wallets cannot pay a mock QR, use the built-in testing mechanisms:

1. **⚡ Bypass Button (On Payment Screen):**  
   Click the yellow **⚡ Bypass** button in the top-right corner of the PaymentScreen. It immediately simulates a successful payment and advances the session to frame selection.
2. **Operator Admin Panel:**  
   Click the **Staff** button (top-right of WelcomeScreen) → Enter PIN `112233` → Go to **Payment** tab → Click **Bypass Active Order**.

## 5. What Is Needed to Enable REAL E-Wallet Payments (Production)?

To allow real customers and founders to scan and pay with real BCA, GoPay, Mandiri, OVO, or Dana accounts:

1. **Active Midtrans Merchant Account:**
   - Must be approved for **QRIS Payment Method** by Midtrans and Bank Indonesia (Acquirer: GoPay or ShopeePay).
2. **Production API Keys:**
   - Obtain from Midtrans Dashboard (Production environment):
     - `MIDTRANS_SERVER_KEY`: Starts with `Mid-server-...` (NOT `SB-Mid-...`).
     - `MIDTRANS_CLIENT_KEY`: Starts with `Mid-client-...` (NOT `SB-Mid-...`).
     - `MIDTRANS_IS_PRODUCTION`: Must be set to `true`.
3. **Update VPS Environment Variables:**
   ```env
   PAYMENT_GATEWAY_ENV=production
   MIDTRANS_IS_PRODUCTION=true
   MIDTRANS_SERVER_KEY=Mid-server-YOUR_REAL_PROD_KEY
   MIDTRANS_CLIENT_KEY=Mid-client-YOUR_REAL_PROD_KEY
   ```
4. **Configure Midtrans Webhook URL:**
   - Set Notification URL in Midtrans Dashboard to:
     `https://api.pictolabs.id/api/payments/webhook`

Once these credentials are set, `isMockKey` evaluates to `false`, and `PaymentsService` will dynamically fetch official Bank Indonesia QRIS barcodes directly from Midtrans Core API.
